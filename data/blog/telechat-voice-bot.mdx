## 为什么做文本 + 语音双输出 Bot？

在通勤、步行或碎片化学习场景下，在 Telegram 里盯着大段纯文本阅读既累眼又不方便。如果机器人既能保留结构清晰的文字答复，又能同步附带一段自然流畅的人声语音播报，就能把聊天窗口变成随时可听的随身知识电台。

**[TeleChat](https://github.com/Jim-purch/telechat)** 采用 **Node.js + `node-telegram-bot-api`** 构建，将 **DeepSeek / Moonshot（Kimi）对话推理** 与 **MiniMax 高拟真语音合成（TTS）** 串联，用户发送文字问题后，Bot 会依次返回文字回复和配套语音消息。

## 核心架构与工作流

```text
[用户 Telegram 客户端]
        │  (发送文本消息或 /命令)
        ▼
[Node.js Bot 监听层 (index.js · node-telegram-bot-api)]
        │  ├─ 读取用户个性化配置 (services/userConfig.js)
        │  └─ 读取/写入多轮上下文 (services/sessionManager.js)
        ▼
[LLM 推理服务 (services/deepseek.js | services/moonshot.js)]
        │  (按用户所选模型生成回复)
        ▼
[MiniMax TTS 合成服务 (services/minimax.js)]
        │  (按用户所选音色生成本地临时音频)
        ▼
[先发文本回复 + 再发语音消息 → utils/fileManager.js 自动清理临时音频]
```

## 关键工程设计

### 1. 用户级个性化配置与多模型热切换

不同于把模型和音色写死在环境变量里的简单脚本，TeleChat 为每位 Telegram 用户维护独立配置（持久化在 `data/userConfigs.json`），支持在聊天窗口直接通过命令实时调整：

- `/models` & `/set_model <deepseek|moonshot>`：在 DeepSeek 与 Moonshot（Kimi）之间随时切换；
- `/voices` & `/set_voice <voice_id>`：浏览 `data/availableVoices.json` 中的 MiniMax 音色列表并自由切换声线；
- `/set_prompt <prompt>`：自定义专属 System Prompt（例如英语口语陪练、技术播客主播）；
- `/set_context <1-20>` & `/clear_history`：灵活控制上下文记忆轮数或一键清空会话。

### 2. 临时音频生命周期与断网自动重连

- **自动清理**：每条回复的音频发送完成后立即调用 `fileManager.deleteFile()` 删除临时文件，防止容器磁盘被音频缓存撑满；
- **状态反馈**：处理长推理与 TTS 合成期间，通过 `editMessageText` 动态更新「🤔 正在思考中... → 🎵 正在生成语音...」，完成后自动撤回状态条，保持对话流清爽；
- **容错重连**：监听 `polling_error`，遇到 `EFATAL`、`ECONNRESET`、`ETIMEDOUT` 等网络抖动自动延迟 5 秒重启轮询，并分流写入 `logs/bot.log` 与 `logs/error.log`。

## 快速配置与 Docker 部署

### 1. 配置环境变量

```bash
git clone https://github.com/Jim-purch/telechat.git
cd telechat
cp .env.example .env
```

在 `.env` 中填入对应凭据：

```env
TELEGRAM_BOT_TOKEN=your_telegram_bot_token
DEEPSEEK_API_KEY=your_deepseek_api_key
DEEPSEEK_BASE_URL=https://api.deepseek.com
MINIMAX_API_KEY=your_minimax_api_key
MINIMAX_GROUP_ID=your_minimax_group_id
MINIMAX_BASE_URL=https://api.minimax.chat
```

### 2. 启动运行（Docker Compose 或本地 Node.js）

```bash
# Docker Compose 构建并后台启动（推荐）
docker compose up -d --build
docker compose logs -f

# 或本地 Node.js 直接运行
npm install
npm start
```

仓库同时提供了服务器一键安装脚本 `deploy.sh` 以及面向无网/受限服务器的离线镜像打包脚本 `build-offline-package.sh`（详见仓库内 `DEPLOY.md` 与 `DOCKER_OFFLINE_DEPLOY.md`）。
