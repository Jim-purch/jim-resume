## 什么是 OH 卡？为什么用 AI 做镜像引导？

**OH Cards（潜意识投射图像卡）** 是心理学与自我觉察领域常用的投射工具，由「图像卡」与「文字卡」两副卡牌组合而成。卡牌没有标准答案，同一张画面在不同心境下会触发完全不同的联想。

传统 OH 卡练习往往需要引导师在旁把控节奏，而普通人日常想要安静地梳理情绪、做一次私密的自我对话时，很难随时找到一位不评判、不说教的倾听者。

**[OH-MindMirror](https://github.com/Jim-purch/OH-MindMirror)** 的目标，就是通过精心的引导提示词与结构化提问词库，让大语言模型充当一个**中立、克制、不带评判的“数字倾听者与镜像引导师”**。

---

## 核心设计与工程实现

### 1. 规避“好为人师”：结合 OH 卡提问手册的引导上下文

很多 AI 心理对话工具最容易让人出戏的地方，在于模型习惯过早下结论或输出大段说教清单。在 **OH-MindMirror** 中，我们在 `constants.ts` 与 `services/geminiService.ts` 中设计了双重约束：

- **角色系统指令（`SYSTEM_INSTRUCTION`）**：约束模型以温和、留白、非评判的方式回应，**严禁直接替用户解读卡牌含义**，而是通过开放式提问帮助用户自行发现联结；
- **文字卡专属提问方向（`createInitialContext`）**：结合仓库内置的 `OH卡提问参考.md`，当用户抽到「图像卡 + 文字卡」组合后，系统会将该文字卡对应的引导方向、图像卡通用观察问题以及图文关联问题动态注入会话上下文：

```typescript
// services/geminiService.ts 核心上下文构造示意
export const createInitialContext = (cards: CardCombination): string => {
  const suggestedQuestions = getWordCardQuestions(cards.word.text)
  return `
[系统事件] 用户抽到了两张 OH 卡：
1. 图像卡：编号 #${cards.image.index + 1}
2. 文字卡：「${cards.word.text}」
...
请以温和、开放、非评判的态度，邀请用户分享他们看到这个组合的第一直觉和感受：
- 不要解读卡牌的意义，让用户自己发现
- 循序渐进，从表层感受开始
  `
}
```

### 2. 抽卡仪式感与多模型兼容架构

- **双卡 3D 翻牌体验（`components/CardDrawer.tsx`）**：内置 89 张图像卡与完整文字卡词库，点击卡背触发洗牌与 3D `rotateY(180deg)` 翻转动画，确认组合后自动开启专属探索会话；对话顶部支持随时展开/收起卡牌大图对照。
- **多 API Provider 自由切换（`components/SettingsModal.tsx`）**：
  - 原生接入 Google `@google/genai` SDK（默认 `gemini-2.5-flash`，可自定义模型名）；
  - 同时兼容任意 OpenAI 格式接口（`provider: 'openai' | 'custom'`），方便用户接入 DeepSeek、硅基流动或本地中转端点。

### 3. 隐私优先的纯前端端侧存储

心理探索记录高度私密，应用采用纯静态 SPA 架构（Vite + React 19 + TypeScript）：

- **零服务端数据留存**：所有探索会话（`oh_card_sessions`）与 API 配置（`oh_card_api_settings`）完全保存在浏览器本地 `localStorage`；
- **BYOK（Bring Your Own Key）直连模式**：用户填入自己的 API Key 后，请求直接从浏览器发往对应模型服务端点；
- **会话归档与导出**：支持侧边栏多会话管理（`HistorySidebar.tsx`）以及一键将完整对话记录导出为本地 `.txt` 文件保存。

## 本地运行

```bash
git clone https://github.com/Jim-purch/OH-MindMirror.git
cd OH-MindMirror

npm install
npm run dev
```

启动后在左下角设置按钮中填入 Gemini 或 OpenAI 兼容 API Key，即可开始抽卡探索。
